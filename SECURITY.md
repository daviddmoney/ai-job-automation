# Security Policy

## Supported version

Security fixes are targeted at the latest code on the `main` branch. Do not assume older deployments receive security fixes.

## Reporting a vulnerability

Please do not report suspected vulnerabilities in public GitHub issues, discussions, pull requests, or screenshots.

Use GitHub's private vulnerability reporting feature for this repository (open the repository's **Security** tab and choose **Report a vulnerability**) when it is available. Include:
- A concise description and affected component or route.
- Reproduction steps and the security impact.
- The affected commit, release or deployment where known.
- A suggested mitigation, if one is known.

Do not include live passwords, API keys, OAuth tokens, refresh tokens, private CVs, personal data, or production database records in a report. Redact proof-of-concept output and use synthetic test accounts/data.

If private vulnerability reporting is not enabled, contact the repository owner through a private GitHub contact channel and request a secure disclosure route. Do not publish exploit details while a report is being coordinated.

## Scope and safe testing

Only test systems and accounts you own or have explicit permission to assess. Do not perform destructive testing, access another user's data, send real job applications or email, or modify production data.

## Response and remediation

Reports will be triaged by severity and exploitability. A fix, mitigation, or request for additional evidence may follow. No fixed response or remediation deadline is promised by this policy.

This policy is a disclosure channel, not a security certification or a guarantee that the application is free of vulnerabilities.
